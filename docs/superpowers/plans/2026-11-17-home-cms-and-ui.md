# CMS home and interface refinement

Approved scope: the owner asked for the homepage to be a CMS page and for a more intuitive, restrained backoffice/public interface with icons and progressive JavaScript/CSS. This authorizes implementation on pipeline-rebuild, not a new main merge or production recreation.

## Product contract

- Treat the reserved CMS page slug `inicio` as the homepage at `/` under both public mounts. It uses the existing typed page document and immutable draft/publication/history/audit lifecycle. No new statistical tables or migration are needed; next free migration remains 0020.
- Preparation is an explicit authenticated, same-origin audited POST, never a GET mutation. Import the existing effective home cards and optional calculated companions, title and introduction into a private draft. Keep the existing home public until the first CMS publication. Do not overwrite an existing document or legacy rows. Source metadata and values stay unchanged.
- Once the CMS home has been published, it owns `/`. Draft changes stay private; restore creates a draft. Unpublication shows a neutral unpublished-home state with navigation, never resurrects legacy cards. Missing/unusable published content must not silently show the old home. Revalidate eligibility for each rendered block; all blocks losing eligibility must remain empty, not trigger fallback.
- A published home has canonical `/`, is excluded from the ordinary `/paginas` listing and avoids duplicate content through the old slug URL. Its preview uses the homepage presentation without publishing and remains static. The retired fixed-home editor is labelled legacy and cannot modify the effective home once prepared.
- Reuse the CMS block renderer for home and ordinary pages, grouping adjacent cards into a responsive grid without changing block order. Preserve SVG cards and local ECharts only when an eligible chart block has a payload. Plain text remains escaped.
- Provide a clear home entry in the CMS dashboard and Admin navigation. Keep the existing form contract/prefix/auth/CSRF, stale-form protection and reason/actor audit.
- Refine the Admin with a coherent navigation shell, labelled actions, meaningful empty/status/error states, readable form groups and clear save/preview/publish hierarchy. Separate content editing from data operation. Icons supplement text and are aria-hidden; self-host a licensed pinned icon font with only needed glyphs. No CDN, analytics or new UI runtime.
- Add modest focus/hover/pressed states and short transitions; respect prefers-reduced-motion. Progressive Admin JavaScript may improve block-field disclosure, option filtering, navigation and unsaved-change feedback, but server-side validation remains authoritative and forms work without JavaScript. Do not silently discard user input or block keyboard navigation.
- On the public side, retain the established editorial identity, improve navigation/buttons/card affordances and spacing; avoid decorative motion and layout shifts. Keep summary pages script-free. Use only local assets and narrowly scoped CSP (`self` font/style and Admin script, no inline execution/eval).
- No changes to collection, statistical calculation, licensing, AI commentary, accounts or shared edge.

## Owner clarification during implementation

The owner explicitly clarified that the deliverable is the CURRENT homepage created as actual CMS content, not merely a mechanism that imports its cards or an empty example. The initial card-only seed is insufficient. Preserve the current hero, highlights, theme directory, verification text and published institutions as editable, ordered page content, with live counts/source facts resolved read-only. Add only the typed CMS blocks/fields needed for those existing sections and normal labelled controls. Do not freeze observation values or source counts into editorial text. Prepare and exercise the populated page on the production copy now; provide an idempotent audited content-initialization path for the separately authorized installation. Existing custom content must never be overwritten or silently published. The original no-new-schema scope still applies.

Browser testing must inspect screenshots and actual controls, not only HTTP status. Local font/JS have no external requests, accessible text survives blocked icons, reduced-motion is respected, old forms work without JS. Human screen-reader acceptance remains separately recorded. A code-only release affects public web and backoffice, not the worker, database schema, Authelia or Traefik.
