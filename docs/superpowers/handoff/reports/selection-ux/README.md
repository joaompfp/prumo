# Batch-selection usability correction

## Scope

The preceding catalogue supported native multi-selection, but its competing per-result one-series notebook action and the Caderno's one-at-a-time quick search made that capability inconsistent. This correction makes multi-selection the primary task on both surfaces. It introduces no schema, source-data, CMS publication, rights, authentication or worker change.

The catalogue has one compact sticky selection bar, live count out of twelve, selected-row feedback and a single primary batch action. Selectable rows retain their statistical detail link but no longer offer a competing one-series notebook. Non-selectable theme rows and existing CMS cards retain their individual entry contracts. The enlarged reading scale, four-significant-figure policy, carmim and icon are unchanged.

Caderno search and result selection share one native form. New checks, deliberate unchecks, off-page addressed references, ordering and chart settings travel through the existing bounded catalogue handoff. Both searching again and applying the selection preserve this state without JavaScript. Invalid addresses are rejected before database work; thirteen references recover visibly in the catalogue without truncation.

A small local progressive script updates counts and selected styles, prevents selecting more than twelve through the enhanced controls and re-enables choices when an item is removed. Native forms remain authoritative. The chart-settings form operates on the applied notebook: pending selection changes block its submit in the enhanced experience and direct the user to apply them first. The no-JavaScript instructions state that apply step explicitly. Unrelated links remain ordinary navigations, not autosave.
