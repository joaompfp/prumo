# CMS-owned comparisons

The owner requires real comparisons to be authored in the backoffice and presented publicly from their published CMS revision. Reader configuration in the Caderno is a separate tool, not editorial publication.

## Implemented scope

The existing immutable CMS chart document supports one to six ordered series, explicit or compatible automatic axis assignments, reviewed time/scale transformations and a comparison category. Native Admin controls expose the same contract, including error recovery and stale-version protection. The public directory is metadata-only, published-only and CMS-owned; comparison details have exact point inspection and disclosed table/definitions/evidence, without composition controls or query overrides. Generic chart blocks reuse the same prepared models.

The versioned `backoffice/comparison_import.py` converts the real prior catalogue exactly once: three original pairs, three Portuguese multiaxis groups and three five-country comparisons. Existing published documents are preserved, private/unpublished collisions are refused before any import writes, and no public GET initializes content. Source values, units, rights and evidence remain outside the CMS writer.

## Release boundary

Only web and backoffice change, with no SQL migration, ingestion restart, ownership, credentials, Authelia or Traefik operation. Install compatible readers first, then explicitly publish the authorized real comparison content through the audited restricted service. Retain the current image/code rollback points, keep the worker identity unchanged and read back exact published heads, Admin controls, public pages and audit after initialization. Preserve existing homepage and source data.

Rolling back code does not delete authored history. Older code cannot edit new analytical chart bodies: retire only these imported publications with the newer editor before downgrading if necessary; never restore the statistical database to undo content configuration. The old built-in public directory would return on an old-code rollback, so it is not an equivalent CMS-operated product.
