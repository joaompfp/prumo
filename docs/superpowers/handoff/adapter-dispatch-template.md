## Lessons from Task 9 that the dispatch MUST encode (each was a real review finding)
1. **Probe ALL active series live, not 3.** Eurostat passed its live test and still failed 150 series in production (confidentiality statuses `|C`/`|N`). Require a full-scope live fetch+parse of every active series of the source (throttled ≤1 req/s, polite UA) and report: series with no data, exceptions, flag/status vocabulary actually observed, quarantine counts. Unknown status/flag codes must raise (never silently 'normal'), but the observed vocabulary must be fully handled.
2. **Registry carries what the adapter needs.** Series in `registry/core.yaml` have no native identifiers (legacy data had only indicator+region): the adapter task must derive `native_code` + `url` per series from the legacy collector (`collectors/<source>.py`, `scripts/`), define and document the format, and set `active: false` (listed in `registry/unmapped-<source>.md` with reason) when it cannot establish the mapping unambiguously, when the registry unit contradicts what the source publishes (unit conflicts), when the series is discontinued/rebased (last value < 2024 — list with successor), or when it duplicates another active series. **Exactly one active series per `native_code`** (test `test_active_native_codes_are_unique`); never a cross_check that is the same source series as its primary. Do not edit units/ids/roles. `registry/core.yaml` is authoritative: `propose_registry.propose` refuses to overwrite it without `force=True`.
3. **Unit-label ↔ source-unit-code table** in a TEST module (`tests/ingest/test_registry_<source>_units.py`): every active series' native unit is in the allowed set for its registry label and every label in use is in the table; flag inconsistent labels for the owner, do not edit registry units. A runtime unit comparison is only meaningful if the verifier reads the unit from a channel independent of the request key; if not, `observed_unit=None` is honest — say so in the report.
4. **Independence.** Adapter and verifier share NO helper module; the verifier uses a different endpoint/format; duplicated tiny parsing (e.g. native_code, status tables) is intentional and commented. The verifier module passes `register_verifier`'s static allowlist (imports only `ingest.http|models|rawstore|sources|verifiers` allowlisted names + stdlib allowlist; read `ingest/verifiers/__init__.py`) and the test calls `assert_verifier_independent(...)` (subprocess guard). Registration happens in the Task 17 CLI.
5. **Numbers are tokens.** Hand over the publisher's number as `str` (`json.loads(parse_float=str, parse_int=str)` or csv text); `'1.10'` stays `'1.10'`; declare `decimal` per series; no floats.
6. **Provenance.** One `RawResponse` per HTTP request; every `RawRow.response_index` points at the response the row came from; no-value cells (confidential/missing) → `value_raw=None` (quarantined `non_numeric`, counted). Every observation stores an explicit flag ('normal' when none) so the verifier always compares one.
7. **Decoder robustness.** Reject truncated payloads (array shorter than declared extent), duplicate period labels, HTML or JSON-error bodies; raw bytes stored untouched.
8. **Tests.** Recorded REAL fixtures (≤200 KB each) hand-cross-checked against the publisher via a THIRD channel; the brief's test names (`test_parse_fixture_yields_expected_rows`, `test_parse_html_error_page_raises`, `test_parse_preserves_status_flags`, `test_verifier_detects_tampered_value`, `test_verifier_registers_and_passes_allowlist`, `test_subprocess_independence`, `test_registry_native_codes_complete`) + a `@pytest.mark.live` test (deselected by default) run once with output pasted.
9. **No independent channel → don't invent one**: list the source in `registry/unverifiable.md`, mark its series inactive/not served, report to the owner (spec §6b). Licences: only confirmed licences have `redistribution_ok: 1`; anything UNVERIFIED stays 0 and must be reported (`registry/licences-todo.md`); the adapter may still be built and tested, the owner/builder confirms terms before serving.
10. Secrets (API keys) live in SOPS `secrets/web.enc.env`; if a key is needed and absent, report NEEDS_CONTEXT — secrets are the owner's.
